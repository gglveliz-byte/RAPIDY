## 2. Flujo end-to-end (UI → hook → tRPC → DB/SSE)

```text
AdminProducts (src/pages/admin/Products.tsx)
├─ Tab "Más vendidos"
│   └─ useQuery(["admin.topProducts", 20])
│       └─ trpcCall GET /api/trpc/admin.topProducts
│           └─ adminQuery (cookie admin + rol admin)
│               └─ order_items ⋈ orders; luego commerces por inArray
│                   └─ agregación en JS → sort por revenue → slice(limit)
├─ Tab "Todos los productos"
│   └─ loadAllProducts()
│       └─ trpcCall GET /api/trpc/admin.listProducts
│           └─ adminQuery
│               └─ products LEFT JOIN commerces (sin límite)
│                   └─ estado local → filtro por nombre en el navegador
└─ Escrituras
    └─ No hay ninguna: el archivo solo importa `trpcCall`.
        Existen `admin.toggleProductAvailability` y `admin.deleteProduct`,
        pero ningún componente las invoca.
```

Puntos verificados del flujo:

- `trpcCall` serializa con superjson y hace `GET` con `credentials: "include"` (`src/hooks/useDeliveryData.ts:59-77`). `trpcMutate` hace `POST` (`:79-98`).
- La ruta está protegida por `<SessionGuard role="admin">` (`src/App.tsx:136`).
- `adminQuery` exige `ctx.admin` y `role === "admin"` (`server/middleware.ts:25-36`). El contexto solo devuelve el usuario si la cookie admin verifica y el rol en DB es `admin` (`server/context.ts:72-95`).
- `products.commerceId` es FK con `onDelete: "cascade"`; `order_items.productId` es FK **sin** acción de borrado (`db/schema.ts:158,221`).
- El canal SSE de cliente es `products:global` (`server/boot.ts:307-326`); el de negocio es `commerce:{id}` (`server/boot.ts:215-236`).
- La página admin **no** abre ningún SSE: no importa `useAdminSSE`, `useProductEvents` ni `useCommerceEvents` (`src/pages/admin/Products.tsx:1-13`).
- El backend admin emite a `commerce:{id}` y `admin:dashboard`, pero no a `products:global` (`server/admin/products-router.ts:120-121,135-136`).

**Riesgo principal de integración:** la moderación admin no invalida el catálogo cliente por SSE y no es enforceable frente al merchant. El checkout sí bloquea, pero la vitrina puede seguir mostrando un producto pausado y el merchant puede reactivarlo. Para un producto con ventas, el borrado admin falla por FK; no queda un mecanismo efectivo de supresión salvo suspender el comercio completo.

## 5. Lo que funciona y no se debe romper

- **Autorización admin:** `listProducts`, `topProducts`, `toggleProductAvailability` y `deleteProduct` están bajo `adminQuery` (`server/admin/products-router.ts:23,47,107,126`), que exige cookie admin válida y rol `admin` (`server/middleware.ts:25-36`). La ruta está bajo `SessionGuard role="admin"` (`src/App.tsx:136`). No se detectó IDOR: el alcance admin es global por diseño.
- **Sin PII ni mass assignment:** las respuestas admin solo contienen datos de producto/comercio; no hay clientes, teléfonos, `passwordHash` ni `fcmToken`. Las mutaciones admin solo aceptan `id`; no aceptan `price`, `image`, `isFeatured` ni `commerceId`, así que no hay mass assignment por esa vía.
- **Sin XSS detectado:** nombre, descripción e imagen se renderizan como texto/atributo en React; no hay `dangerouslySetInnerHTML` en las vistas de producto. El esquema de imagen bloquea `javascript:` y data URLs SVG; solo permite HTTPS o JPG/PNG/WEBP (`server/product-router.ts:19-29`).
- **Listado sin N+1:** `listProducts` resuelve comercio con un solo `LEFT JOIN` (`server/admin/products-router.ts:25-43`). `topProducts` ya no hace una consulta por comercio: usa `inArray` (`:71-79`). No reintroducir el N+1 histórico del ledger admin.
- **Validación de precio/imagen:** `priceSchema` exige decimal positivo, máximo de 8 enteros + 2 decimales, sin exponenciales (`server/product-router.ts:10-17`); `imageSchema` limita a 2.000.000 caracteres y valida MIME (`:19-29`). `quote` vuelve a validar precio máximo (`server/order-router.ts:151-159`).
- **Filtros públicos:** `product.list`, `getFeatured` y `search` exigen `isAvailable = "yes"`, comercio `active` e `isOpen = "open"` (`server/product-router.ts:75-88,129-143,184-203`). `getByCommerce` exige comercio `active` y producto disponible; el cierre del local lo maneja la vitrina (`server/product-router.ts:113-126`). `commerce.getById` devuelve `null` a no-owner si el comercio no está `active` y filtra productos (`server/commerce-router.ts:79-86`). Es el comportamiento reciente que no se debe revertir.
- **Quote/create server-side:** el precio, subtotal, comisión y total se calculan en servidor; el cliente no puede imponer montos (`server/order-router.ts:106-216,437-443`). Un producto pausado/agotado no se compra aunque la UI esté vieja.
- **SSE del merchant:** `product.create/update/delete` emiten a `commerce:{id}` y `products:global` (`server/product-router.ts:215-216,252-253,279-280`); `useProductEvents` invalida las consultas correctas (`src/hooks/useOrderEvents.ts:210-229`). Este es el patrón que debe usar la moderación admin.
- **Borrado merchant con FK:** el router merchant captura 23503 y devuelve un `CONFLICT` explicativo (`server/product-router.ts:287-291`). Es el patrón que le falta al router admin.
- **Estados de la tab “Todos”:** tiene loading, error con reintento y empty state (`src/pages/admin/Products.tsx:209-222,282-288,294-296`). No romperlos al añadir acciones.
- **`commerce.getById` con filtro `active`:** la excepción owner/admin es intencional y permite moderar comercios suspendidos; el público no los ve (`server/commerce-router.ts:79-86`).

## 7. Resumen para consolidado (top 5)

1. **ADM-PROD-01 — P1 — La ruta admin es solo lectura.** No hay acciones de disponibilidad, destacado, edición ni borrado; las mutaciones del backend están muertas. `src/pages/admin/Products.tsx:228-280`; `server/admin/products-router.ts:107-138`.
2. **ADM-PROD-02 — P1 — La pausa admin es reversible por el merchant.** `product.update` acepta `isAvailable` y solo valida ownership. `server/admin/products-router.ts:107-123`; `server/product-router.ts:50-51,230-253`.
3. **ADM-PROD-03 — P1 — La moderación no llega al catálogo cliente por SSE.** Admin emite solo `commerce:{id}`/`catalog_update`; el cliente escucha `products:global`/`products_update`. `server/admin/products-router.ts:120-121,135-136`; `server/boot.ts:307-326`; `src/hooks/useOrderEvents.ts:210-229`.
4. **ADM-PROD-04 — P1 — `listProducts` es ilimitado y devuelve base64 completo.** Sin paginación, con imágenes de hasta 2 MB y campos no usados. `server/admin/products-router.ts:23-43`; `src/pages/admin/Products.tsx:32`.
5. **ADM-PROD-06 — P1 — Borrar un producto con ventas devuelve 500.** `order_items.product_id` bloquea el `DELETE` y el router admin no captura 23503. `server/admin/products-router.ts:133`; `db/schema.ts:221`; `server/product-router.ts:287-291`.

**P1 adicional (6.º):** **ADM-PROD-05** — `topProducts` escanea todo el historial de `order_items` y agrega en JS; debe pasar a agregación SQL con límite (`server/admin/products-router.ts:47-97`).

**Riesgo de integración para el consolidado:** el checkout bloquea correctamente productos pausados/agotados, pero `/home`, `/search` y `/store/:id` pueden quedar obsoletos por falta de SSE global, y el merchant puede revertir la pausa admin. La moderación efectiva de un producto con historial hoy no existe: no se puede borrar por FK y la pausa no es enforceable.
